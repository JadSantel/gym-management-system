# Design System: Form & Function

## Overview

The user-selected shadcn preset `b5J4p8Yqm` (November 10, 2026) establishes Nova styling, neutral theme and base, Inter, Lucide, sky charts, default radius, and subtle menu accents. It supersedes the October 30 prototype's warm paper, Geist, and orange identity. Mode: Operate. The same operational content and protected workflows continue inside the replacement visual system.

**Key Characteristics:**
- Neutral light surfaces and charcoal dark layers, with paired semantic foregrounds.
- Self-hosted Inter and tabular amounts.
- Flush sidebar-01 groups with direct navigation and a restrained selected surface.
- Sky data marks with labels and pattern distinctions; explicit semantic statuses.

The preset and historical prototype are presentation input, not product-policy authority. `docs/PROJECT.md` and `docs/architecture.md` still control authorization, money, time, history, and data boundaries. Fictional names, totals, attendance, role switching, and simplified verification logic in the prototype are not application behavior.

## Colors

`globals.css` owns the normative light/dark semantic pairs, mapped to Tailwind tokens. Light uses white content surfaces and a lightly differentiated sidebar; dark uses neutral charcoal layers. Primary actions reverse ink/paper between themes. Existing brand aliases resolve to primary/accent, with no orange identity. Sky chart tokens color collections and occupancy. Green means effective or confirmed; amber means attention; red means blocked/destructive. Color always accompanies text.

**The Semantic Pair Rule.** Keep background/foreground pairs together in both themes. The preset's muted foreground and input borders have explicit contrast overrides in the runtime tokens.
The shared `scrim` token darkens the content behind a modal drawer by 50% in either theme.

Members uses neutral, border-led summary cards, search/table and a registration dialog in both themes. The duplicate Front Desk banner and its decoration have been removed. No charcoal content panel is imported into light mode. Dashboard collections distinguish confirmed Cash and Online with solid and hatched bars, explicit method labels and daily amounts. Retired financial/operational records remain preserved and read-only in linked history.

## Typography

Self-hosted Inter Variable (upright, weights 100-900), copied unmodified from upstream rsms/inter. The active font and its SIL OFL license are in `public/fonts/`; the former Geist asset remains historical and is not loaded. No external font request. Page headings are 28px/600 with -0.03em tracking; 24px on phones. Section titles are 15px/600. Body is 14px, field text 16px, supporting text 12px. Amounts use tabular numerals. Status and table labels use restrained tracking, never color alone. Long references wrap.

## Elevation & Depth

Flat surfaces use one-pixel semantic borders or the Nova Card's one-pixel foreground-tinted ring. The flush sidebar has a separating border and no floating-card shadow. Active navigation uses a neutral selected surface, paired foreground, and `aria-current`. Members retains one directory with membership status and exact dates, with creation in a dialog; profiles retain current admission checks and payment access. No stock imagery, raster comps, fake charts, or fabricated activity.

## Shapes

The preset base radius is 0.625rem. Shared controls and avatars use its large radius; generic panels use its extra-large radius. Nova Card defaults to extra-large corners with 16px spacing (12px for its small variant); dense dashboard and attendance Cards explicitly use large corners. Status labels retain their established compact corners. Local shadcn Card/Badge remain editable source. Controls retain 44px minimum targets, visible focus, semantic input strokes, and disabled/busy states.

Membership enrollment imports Button, Input, Label, Badge and Separator; native plan/method radios, provider select and funds-checked checkbox retain standard keyboard behavior. Personal QR uses Card, Button and AlertDialog for destructive replacement. Dialog and AlertDialog use the existing semantic scrim, local Button and shared `cn` utility. Native date inputs, selects, labels, checkbox confirmations, and other tables remain where simpler.

**The Scroll Access Rule.** The shared Table wrapper is a keyboard-focusable, horizontally scrollable region with a visible semantic focus outline. Its accessible name derives from the table's aria-label with "scroll area" appended, or defaults to "Table scroll area". Preserve the native table, header and cell semantics inside that region, including when an empty table still needs horizontal scrolling.

Members offers All members / Active / Expiring soon / Pending. Active means a currently effective verified paid or owner-approved legacy interval. Expiring soon overlaps Active when the current interval has more than zero and at most seven elapsed 24-hour days remaining, including the exact seven-day threshold. A prepaid next term does not remove that current term from Expiring soon; it is separately labelled “Paid next term scheduled.” Pending means no verified membership history yet; scheduled, expired and withdrawn-history records are not Pending. Dates show the current interval, otherwise the next scheduled or latest expired interval, in PHT with an exclusive expiry. “View customer” opens the existing member profile; “View payment details” opens its `#member-payments` section. Route-local loading and retryable error boundaries cover the directory read.

The shell displays the authenticated role; it has no demo role switch. Appearance remains Light/Dark/System, persisted with pre-paint initialization, live system preference updates, and storage failure fallback. Existing identity summaries, field associations, focus restoration, permission filtering, and server authority remain. Settings actions require the active owner session without repeat password verification.

The navbar's right utility group follows the November 2 reference: live Manila time with seconds, PHT/date, an icon Appearance button and the far-right operator account button. Local Button/Popover primitives provide theme choices; local DropdownMenu provides Settings and Log out with icons. Initials, name and Owner/Staff replace the old sidebar identity block; only gym/synthetic context stays in its footer. Phone layouts retain the initials and role while hiding the longer name and route label. The device clock is informational; server business timestamps remain authoritative.

Settings reuses Button and Input with active-owner authorization and focused feedback patterns, without repeat password verification. Profile editing is owner-only; staff read gym details. Contact email is separate from login identity. Timezone, country and currency are profile labels; payments and receipts remain PHP, and membership dates and clock remain Asia/Manila.

Membership enrollment follows the November 7 Plan, Payment, Review revision within this existing visual system. Cash and Online (GCash, GoTyme, MariBank) use the same exact full-charge confirmation. Online adds provider, transaction reference and a checkbox stating that the collecting operator personally checked full received funds and the reference in the gym receiving account; changing provider, reference or amount clears that attestation. Owner or Staff with existing collection permission can collect either method; preparing a charge also requires member-management access. Missing permission, an empty catalogue, stale saved terms, an already paid future term and unavailable recovery storage have explicit blocked states. Errors receive focus, step changes move focus to the heading, busy controls prevent repeat actions, and confirmation offers the durable receipt reference/link. Shared unknown-operation recovery preserves the original method, key, amount, member, charge and Online evidence, blocks a new charge or method switch, and offers resolution of that original operation without collecting again. The earlier November 1 digital-collection retirement is superseded only for this enrollment flow; Exceptions, outage receipt/custody and daily closing remain retired. Owner-only Reports follows FR-16, composing local Card, Button, Input and Table with Tabs from the installed `radix-ui` package. Member-account scope follows the later FR-15 revision in PROJECT.md.

FR-13 adds public member registration and unverified contacts within this visual system. FR-14 implements personal QR issuance/export/replacement, staff-operated Scanner, attendance history and audited visit corrections within the same world. Creating a member alone grants no paid access. Front Desk lookup/eligibility, member creation and profile/payment access are unified at `/members`; the directory preserves the existing creation fields and profile/payment workflows; Add member and the Add Members sidebar action open the same registration dialog. The old desk layout is removed. `/operate` remains a temporary 307 compatibility redirect to `/members`, without a navigation destination; authorization remains enforced by the destination and APIs. Cash shortcuts target `#search-name`; creation shortcuts open `/members?add=member`. The earlier Members redesign preserved navigation and authorization; the November 10 task replaces sidebar presentation while retaining capability filtering and tenant isolation. Retried enrollment operations retain their original key, amount, member, charge and method evidence. Registration creates a profile; attendance records arrivals/departures separately from payment and entitlement. Recorded optional phone/email contacts follow FR-13; missing values remain Not recorded.

## Do's and Don'ts

- Follow the selected Nova neutral/Inter/sky system and actual product data; retain existing workflow composition.
- Keep every state legible in both themes and at phone/tablet/desktop sizes.
- Preserve server authorization, exact centavos, PHT boundaries, and append-only history.
- Never infer total-gym metrics from a capped search result or call pending funds confirmed.
- Never treat prototype simulation, local verification, or screenshots as pilot/live readiness.
