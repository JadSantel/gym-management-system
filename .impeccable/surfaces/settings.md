# Settings

Scope: top-right operator menu and `/settings`, `/settings/plans`, `/settings/team`. Mode: Operate. Inherit the established design system; user-supplied references pin the two-item icon menu and settings side navigation.

THESIS: Gym configuration has one predictable home, with contact details separate from account identity and financial rules.

OWN-WORLD: Existing Geist, neutral light and charcoal dark tokens, orange selection, local shadcn controls and Lucide icons. No new visual system.

STORY: Open Settings; choose Profile, Plans and Pricing, or Team and Access. Owners review and edit the gym profile using their active owner session, without a repeat password prompt. Staff read gym details and their own account; existing owner restrictions remain. Editable timezone/country/currency are profile labels only, as explicitly selected by the user; payments/receipts stay PHP and membership dates/clock stay Asia/Manila.

FIRST VIEWPORT: Settings heading above a 220px section navigation and flexible detail area. Profile leads with gym identity, Edit profile, and a two-column labelled detail grid with full-width address. Phone navigation stacks above the single-column details. Error feedback focuses and links to invalid fields; saving/cancel returns to Edit profile.

FORM: Reference-pinned settings composition, inherited application system. No concept roll needed for this precisely specified extension. Code-led build; seed: none (reference-pinned).

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance
